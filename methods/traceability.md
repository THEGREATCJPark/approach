# 수용 기준과 증거 연결 / Acceptance Traceability

- id: `traceability`
- 사용할 때: 테스트는 있지만 사용자 요구를 보장하는지 모르겠다
- 사용하지 않을 때: 모든 코드 줄에 문서 번호를 붙이느라 핵심 검증을 늦춘다
- [공개 1차 참고](https://cucumber.io/docs/gherkin/reference/) — 2026-11-05 확인.

## 5~15분 실행

사용자 결정 한 개에 수용 기준을 붙이고 정상·보류 입력을 적는다. 구현 위치·검사·실제 결과·보장하지 않는 것을 한 줄로 연결한다.

시간은 이 저장소의 연습 권장 예산이며 원저자의 규격이나 실행시간 보장이 아니다. 아래 절차·기록 형식은 업무 도구 개발에 맞춘 독립적인 적용 제안이다.

## 남길 결과

요구 ID→구현 위치→검사→실제 결과→한계

## 중단·오용 방지

핵심 결정마다 적어도 한 증거와 한 한계가 연결되면 종료.

피할 오용: 테스트 개수로 누락 요구를 가리거나 사용자 효과를 단위 테스트로 입증한다. 실제 업무 증거가 없으면 합성 연습으로 표시한다.

## 다음 연결

관련 사례의 데이터 계약과 정상·경계·정보 부족 기대값을 읽는다. [진입점](../START_HERE.md)에서 실제 허용 범위를 먼저 확인한다. 설명 연습은 사전 연습에서만 사용하며 AI 금지 실제 평가에는 적용하지 않는다.
