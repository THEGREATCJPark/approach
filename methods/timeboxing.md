# 시간 제한·중단점 / Timeboxing

- id: `timeboxing`
- 사용할 때: 잔여 시간이 불확실하고 선택 기능이 늘어난다
- 사용하지 않을 때: 고정 시간을 실제 실행시간 보장으로 말한다
- [공개 1차 참고](https://scrumguides.org/scrum-guide.html) — 2026-11-05 확인.

## 5~15분 실행

잔여 시간을 확인하고 첫 경로·검증·정리 구간을 배분한다. 중간 시점에 실제 출력이 없으면 선택 기능·새 프레임워크를 빼는 조건을 적는다.

시간은 이 저장소의 연습 권장 예산이며 원저자의 규격이나 실행시간 보장이 아니다. 아래 절차·기록 형식은 업무 도구 개발에 맞춘 독립적인 적용 제안이다.

## 남길 결과

체크포인트/필수 출력/실패 시 축소/재개 조건

## 중단·오용 방지

정해진 시점에 결과·축소·중단 중 하나를 선택.

피할 오용: 시간 부족을 이유로 필수 규칙·실제 데이터 연결·검증을 조용히 삭제한다. 실제 업무 증거가 없으면 합성 연습으로 표시한다.

## 다음 연결

관련 사례의 데이터 계약과 정상·경계·정보 부족 기대값을 읽는다. [진입점](../START_HERE.md)에서 실제 허용 범위를 먼저 확인한다. 설명 연습은 사전 연습에서만 사용하며 AI 금지 실제 평가에는 적용하지 않는다.
