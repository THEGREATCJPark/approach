# 상황·목적 구분 / Job Story

- id: `job-story`
- 사용할 때: 기능 요청은 있는데 사용 상황과 성공 결과가 불명확하다
- 사용하지 않을 때: 규정상 확정된 필수 기능을 목적 재해석으로 제거하려 한다
- [공개 1차 참고](https://www.intercom.com/blog/using-job-stories-design-features-ui-ux/) — 2026-11-05 확인.

## 5~15분 실행

상황, 하고 싶은 행동, 얻고 싶은 결과를 세 문장으로 쓴다. 기능명은 지운 뒤 현재 대체 방법과 비교한다.

시간은 이 저장소의 연습 권장 예산이며 원저자의 규격이나 실행시간 보장이 아니다. 아래 절차·기록 형식은 업무 도구 개발에 맞춘 독립적인 적용 제안이다.

## 남길 결과

상황/동기/결과 및 확인한 관찰 한 건

## 중단·오용 방지

사용자 다음 행동과 결과를 한 문장으로 합의하면 종료.

피할 오용: 가상의 인구통계나 기능 취향을 실제 동기 근거로 쓴다. 실제 업무 증거가 없으면 합성 연습으로 표시한다.

## 다음 연결

관련 사례의 데이터 계약과 정상·경계·정보 부족 기대값을 읽는다. [진입점](../START_HERE.md)에서 실제 허용 범위를 먼저 확인한다. 설명 연습은 사전 연습에서만 사용하며 AI 금지 실제 평가에는 적용하지 않는다.
