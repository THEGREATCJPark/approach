# README 입력 흐름의 정적 점검

확인일: 2026-11-05. 이번 변경은 문서 흐름과 독립 창작 입력/응답 예시다. 기존120개 사례·라우터 코드·계산 예제는 수정하지 않았다.
검사 방식은 manual_static_check다. 아래 조건에 대해 진입 문서·전용 절차·응답 양식·창작 예시를 대조했다.
독립 모델을 실행해 답변을 생성하지 않았으므로 모델 지침 준수율·실제 사용자 검증·새 라우터 정확도로 주장하지 않는다.

| 입력 조건 | 요구하는 응답 동작 | 정적 확인 |
|---|---|---|
| 완전한 README를 붙여넣음 | 받은 원문을 다시 요청하지 않고 요구별 구현/검증 연결 | 진입 문서와 절차에 명시 |
| CSV가 본문에만 언급됨 | 파일명 확인과 실제 열람을 구분, 행수·관찰 결과를 만들지 않음 | 창작 응답에서 미열람 명시 |
| 고정 노선 조회 웹 | 조회/필터/상세부터 시작, 노선 최적화 추가 금지 | 창작 예시 R1~R5로 연결 |
| 시간 조정·용량 배정·방문 순서로 요구 변경 | 실제 결정에 따라 방법 전환 | 절차의 분기표와 예시 분기 확인 |
| 조건이 충분하거나 제한 시간이 없음 | 질문0개 허용, 임의의180분 가정 금지 | 양식·절차에 명시 |
| 원문 충돌 또는 저장소 접근 실패 | 상충 근거와 영향 표시, 미열람 경로와 잠정 계획 구분 | 절차에 명시 |
| 접근법만 요청 / 구현까지 지시 | 전자는 계획부터, 후자는 확인된 범위 실행; 중복 승인 요구 없음 | 진입점·양식·절차 일치 |
| 실제 AI 금지 평가 단계 | 질문 생성·답변 작성·실시간 코칭 중단 | 기존 경계 유지, 새 문서에도 명시 |

예시의 수치 기대값은 sequence 정렬이다. 합성 입력[3,1,2]를 오름차순으로 정렬하면[1,2,3]이며, 정류장·시각이 있는 행 전체가 함께 이동해야 한다.
이는 실제 CSV에 대한 실행 결과가 아니다. 실제 데이터·앱·UI·사용자 피드백은 이후 허용된 과제 공간에서 검증해야 한다.
내부 경로와 공개 파일 패턴 검사는 갱신된 integrity-results.json과 publication-results.json에 기록했다.
기존120개 사례의 합성 계산487개를 재실행해 모두 통과했다. 새 README 응답 예시를 모델로 실행한 결과는 아니며, 사례 수나 신규 테스트 수에 중복 합산하지 않는다.
