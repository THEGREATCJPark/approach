## 요청과 다른 해석

“지역 자료실의 주간 읽기 목록 세 편이 매번 같은 주제로만 채워진다.”

- 점수 순위는 유지하되 동일 주제 두 편까지만 허용하고 싶다.
- 주제 분류 오류 때문에 편중처럼 보일 수 있다.
- 편중이 실제 독자 불만인지 운영자의 가정인지 확인해야 한다.

## 우선 질문과 방향 변화

1. 주제 제한은 필수인가 선호인가? → 필수면 위반 없이 부족분을 남기고, 선호면 점수 손실과 함께 비교한다.
2. 복수 주제 글은 어떻게 세는가? → 단일 대표 주제 합의 전 다중 할당을 추측하지 않는다.
3. 동점은 무엇으로 정하는가? → 안정적 id 순 또는 명시된 게시일 정책을 쓴다.

파일에서 이미 확인되는 답은 다시 묻지 않는다. 정책을 결정할 권한자와 기준 시점을 함께 기록한다.

## 데이터 계약과 합성 입력

글 한 행. id 기본키, topic 단일 주제 코드, score 정수 선호 점수(확률 아님). 목록 크기 k=3, 주제별 cap=2.

최소 필수는 아래 판정 필드와 키다. 대표 샘플·스키마로 시작하며 개인 식별 정보는 필요하지 않다. 개선용 데이터는 실제 작업 시간과 오류 기록이다. 전체 이력이나 외부 API는 첫 검증에 없어도 된다. null은 미확인이며 0·false와 다르다. 필수 필드가 없으면 해당 판정을 보류하고 담당자 확인 목록에 남긴다.

## 기준 방법, 제약과 최소 경로

점수 내림차순을 훑으며 주제별 한도를 넘는 항목을 건너뛴다. 이 단일 주제 상한과 동일 슬롯 문제에서는 조합 열거를 작은 정답 기준으로 사용한다. 복합 제약에서는 탐욕 최적성을 일반화하지 않는다.

필수: 중복 id 없음, k개 이하, 주제 cap 이하. 선호 목적: 선택 점수 합 최대. 수량 미달이면 빈 칸과 이유를 표시한다. 동점은 id 순.

글 목록 → 무제약 ABC(24)와 제약 ABD(23) 비교 → 담당자가 편중 제한에 따른 1점 손실을 보고 목록을 확정한다.

## 기대 결과와 반례

| 유형 | 입력 또는 변경 | 기대 결과 |
|---|---|---|
| 정상 | k=3,cap=2 | A,B,D; 합23 |
| 경계 | cap=1,k=3 | A,D,E; 합20 |
| 정보 부족 | D topic=null | D 보류; A,B,E 합22 |
| 충돌 | cap=1,k=4,주제3개 | 최대3편, 1편 미충족 |
| 중복 | A 행 두 번 | 중복 id 입력 오류; 점수 두 번 합산 금지 |
| 새 샘플 | F 공예 점수10 추가 | F,A,B; 합27 |

손계산 근거: 무제약 9+8+7=24. 자연 세 편은 cap2 위반이므로 7 대신 역사6 선택:23. cap1은 9+6+5=20. 모든 3개 조합 열거와 대조한다.

비슷하지만 다른 두 건: cap2는 ABD, cap1은 ADE다. 단순히 최종 목록에 다양성 라벨만 붙여서는 결과가 바뀌지 않는다.

작은 계산 예제는 [check_c.py](../../examples/synthetic/check_c.py)에서 별도 표준 라이브러리 계산으로 확인한다. 각 수용 테스트 행의 기대값은 소형 오라클 계산으로 확인한다. 전체 앱·화면·DB 동시성은 구현하거나 검증하지 않았으며, 기대값 검증과 구현물 테스트 통과는 다르다. 실행 범위는 해당 스크립트 출력과 검증 보고서를 따른다.

## 답변이 바뀌면 수정할 계획

- 주제 상한을 선호로 바꾸면 별도 페널티를 담당자와 정하고 기존 필수 기준 결과를 보존한다.
- 개인별 읽기 목록이 필요하면 공통 점수를 개인 점수로 바꾸되 동의 없는 프로필 수집은 하지 않는다.

## 피할 구현과 축소 기준

- 항목 간 복합 의존 제약에는 이 탐욕 방식의 최적성을 주장하지 않는다.
- 점수를 만족도나 성공 확률로 표시하지 않는다.
- 시간 부족이면 개인화 모델 대신 조합 비교와 한도 준수만 만든다.

1순위 도구는 [Python 표준 라이브러리](../../tools/python-stdlib.md)다. 이 작은 합성 입력에는 패키지 설치·외부 호출이 필요 없다. Python도 실행할 수 없으면 표에 후보를 전부 적고 손계산한다. 대규모 개선 도구는 설치·규정·입력 적합성이 확인된 이후 별도 선택한다.

## 연습 시간 예산과 효과 측정

30분: 10개 조합 열거. 90분: 목록과 점수 손실 표. 180분: 제약 편집과 재계산. 권장 연습 예산이다.

주제 한도 위반 수, 선택 수, 기준 순위 대비 점수 차이를 측정한다. 이 합성 예제만으로 실제 조직의 시간 절감·만족도·수익 향상을 주장할 수 없다.
