## 창작 요청과 가능한 원인
창작 요청: 공방 물류 담당자가 내일 행사에 쓸 재료를 발주하려는데 다음 주 입고 예정량까지 가용 재고로 잡혀 부족이 발생한다.

- 총 입고량과 필요시점 이전 입고량을 혼동한다.
- 포장 단위 반올림을 일반 반올림으로 계산한다.
- 안전재고와 이미 예약된 재고가 중복 반영된다.

## 먼저 가를 질문
| 질문 | 답에 따른 방향 |
|---|---|
| 수요는 확정 사용량인가 예측인가? | 예측이면 시나리오별 발주량으로 표시하고 확정 주문과 분리. |
| 어느 시점까지 도착한 재고만 쓸 수 있는가? | 마감시점 이전 입고만 차감한다. |
| 팩을 쪼개거나 최소 주문량이 있는가? | 분할 불가면 올림, 최소 주문량이 있으면 추가 제약. |

## 데이터 계약과 합성 입력
최소 필수: demand, safety, on_hand, reserved, timely_inbound, late_inbound(개), pack(개/팩). 한 객체는 하나의 품목·필요시점. null은 미확인이고 0은 확인된 없음. 품목 id/기준시점은 관계키. 리드타임은 있으면 개선; 단가 없이는 금액 계산 제외.

```json
{
  "item": "fiber",
  "demand": 23,
  "safety": 4,
  "on_hand": 8,
  "reserved": 2,
  "timely_inbound": 5,
  "late_inbound": 12,
  "pack": 6
}
```

## 기준 방법과 최소 구현
필요량=max(0,수요+안전재고−(보유−예약)−기한내입고). 팩 수=필요량/팩크기 올림. 늦은 입고는 이번 가용량에서 제외한다.

여러 품목의 공동 운송·최소 구매액·불확실 수요가 확인되면 시나리오 분석이나 정수 최적화를 검토한다.

품목별 수량/시점 → 가용량과 순필요 계산 → 발주 제안·잔량 → 담당자가 주문 승인

목적: 필요시점 부족 방지. 필수: 정수·비음수·팩양수·예약≤보유. 선호: 과잉 최소는 최소 팩 수로 실현. 발주 실행은 별도 승인과 멱등성 필요.

## 반례와 기대값
| 종류 | 입력 변화 | 기대 출력 | 계산·판정 근거 |
|---|---|---|---|
| 정상 | `{}` | `{"net": 16, "packs": 3, "order": 18, "surplus": 2}` | 23+4−(8−2)−5=16,ceil(16/6)=3. |
| 경계 | `{"demand": 7}` | `{"net": 0, "packs": 0, "order": 0, "surplus": 0}` | 7+4−6−5=0. |
| 정보 부족 | `{"demand": null}` | `"unknown"` | 미확정 수요는0이 아님. |
| 충돌 | `{"reserved": 9}` | `"invalid"` | 예약9가 보유8을 초과하는 예제 입력은 확인 필요. |
| 재시도 | `{"repeat": true}` | `{"net": 16, "packs": 3, "order": 18, "surplus": 2}` | 계산 재실행은 주문 생성이 아니다. |
| 새 표본 | `{"pack": 5}` | `{"net": 16, "packs": 4, "order": 20, "surplus": 4}` | 포장 변경으로20개 주문. |

입력 변화는 위 합성 입력에 적용한다. `only`, `events`, `values`는 전체 입력 교체, 그 외는 해당 항목 변경이다. 테스트 실행 코드가 변형의 정확한 의미를 정의한다.

독립 기대값 근거: 가용량=(8−2)+5=11개, 목표량23+4=27개, 부족16개. 6개팩2개는12개로 부족,3개는18개로2개 남음. 늦은12개를 빼면 부족4개라는 오류가 생김.

서로 비슷하지만 달라야 하는 두 건: 기한내 입고5개일 때 주문18개, 늦은12개를 잘못 합치면 주문6개로 과소 발주.

## 답변 변화와 범위 통제
- 예약량이 이미 on_hand에서 빠졌다는 답변 → 이중차감 제거하고 필드 명세 변경.
- 배송이 지연될 수 있다는 답변 → 확정과 위험 입고를 분리한 시나리오 제공.

예제는 발주 제안 계산이며 주문 시스템이 아니다. 예측 모델을 붙여 데이터 시점 오류를 감추지 않는다. 단위 미확정이면 계산을 멈추고 변환표부터 받는다.

## 시간과 도구
연습용 권장 예산이며 실제 실행시간 보장이 아니다.
- 30분: 위 합성 입력 한 건과 반례를 손으로 계산하고 필수 정책 1개를 확인한다.
- 90분: 데이터 입력 → 판정/계산 → 근거와 다음 행동까지 연결하고 아래 6개 검사를 실행한다.
- 180분: 담당자 피드백으로 오해가 있는 표현을 수정하고 실제로 추가된 조건만 반영한다.
- 1순위: Python 표준 라이브러리. 설치 없이 소형 계산·집계·완전탐색을 재현한다. 설치/실행 불가 시 표 계산 또는 종이 결정표로 동일 기대값을 대조한다.
- 실행 허용이 unknown이면 자동 실행하지 않고 Markdown과 합성 표를 읽는 경로를 사용한다.
