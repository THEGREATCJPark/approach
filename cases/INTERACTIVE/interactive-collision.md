## 요청과 다른 해석

“짧은 격자 탐험에서 벽에 부딪혔는데 캐릭터가 통과하거나 에너지가 두 번 줄어든다.”

- 충돌 검사와 좌표 갱신 순서가 잘못됐을 수 있다.
- 동일 입력 이벤트 중복 처리일 수 있다.
- 렌더링 프레임마다 에너지를 빼는 시간 모델 오류일 수 있다.

## 우선 질문과 방향 변화

1. 막힌 이동도 에너지를 소비하는가? → 연습 정책은 소비하지 않으며 다르면 기대값을 변경한다.
2. 한 입력은 한 칸인가 지속 이동인가? → 한 칸이면 이벤트 기반, 지속이면 dt 기반을 택한다.
3. 네트워크 동시 플레이가 필요한가? → 아니면 단일 로컬 상태로 범위를 고정한다.

파일에서 이미 확인되는 답은 다시 묻지 않는다. 정책을 결정할 권한자와 기준 시점을 함께 기록한다.

## 데이터 계약과 합성 입력

board width/height 정수 칸수, walls 좌표 배열. player x/y 정수, energy 정수. event id 고유키, dx/dy는 상하좌우 한 칸만. 이벤트 처리 기록은 동일 세션 내 중복 방지용이다.

최소 필수는 아래 판정 필드와 키다. 대표 샘플·스키마로 시작하며 개인 식별 정보는 필요하지 않다. 개선용 데이터는 실제 작업 시간과 오류 기록이다. 전체 이력이나 외부 API는 첫 검증에 없어도 된다. null은 미확인이며 0·false와 다르다. 필수 필드가 없으면 해당 판정을 보류하고 담당자 확인 목록에 남긴다.

```json
{
  "board": {

    "height": 3,
    "walls": [
      [
        2,
        1
      ]
    ]
  },
  "player": {
    "x": 1,
    "y": 1,
    "energy": 3
  },
  "events": [
    {
      "id": "e1",
      "dx": 1,
      "dy": 0
    },
    {

    {

}
```

## 기준 방법, 제약과 최소 경로

입력 검증 → 이미 처리한 id 제외 → 후보 좌표 경계/벽 검사 → 허용된 이동만 좌표와 에너지를 한 번 갱신한다. 렌더링은 상태를 읽기만 한다.

필수: 0≤x<4,0≤y<3, 벽 점유 금지, energy≥0. 에너지0이면 새 이동 불가. 목적함수는 없으며 상태 전이 규칙의 일관성을 확인한다.

이벤트 목록 → 상태 reducer → 위치(1,2), 에너지2, 마지막 이유 duplicate → 사용자는 다음 가능한 이동을 선택한다.

## 기대 결과와 반례

| 유형 | 입력 또는 변경 | 기대 결과 |
|---|---|---|
| 정상 | e1 벽,e2 아래,e2 재시도 | (1,2),energy2 |
| 경계 | (0,0)에서 왼쪽 | 위치·에너지 유지, 경계 사유 |
| 정보 부족 | dx=null | 입력 오류, 상태 불변 |
| 충돌 | (1,1)에서 오른쪽 | 벽 때문에 (1,1),energy3 유지 |
| 중복 | 성공 e2 두 번 | 에너지 한 번만 감소 |
| 새 샘플 | 새 id로 위쪽 이동 | (1,0),energy2 |

손계산 근거: 초기3에서 벽 이동은0 소비, 아래 한 칸만1 소비:2. 중복 e2는 다시 소비하지 않는다.

비슷하지만 다른 두 건: 같은 방향이라도 같은 id 재시도는 무시하고 새 id 이동은 새 행동이다. 위치가 같다는 이유로 중복을 판정하지 않는다.

작은 계산 예제는 [check_c.py](../../examples/synthetic/check_c.py)에서 별도 표준 라이브러리 계산으로 확인한다. 각 수용 테스트 행의 기대값은 소형 오라클 계산으로 확인한다. 전체 앱·화면·DB 동시성은 구현하거나 검증하지 않았으며, 기대값 검증과 구현물 테스트 통과는 다르다. 실행 범위는 해당 스크립트 출력과 검증 보고서를 따른다.

## 답변이 바뀌면 수정할 계획

- 막힌 이동도 소비하도록 바뀌면 실패 이동을 상태 전이에 포함하고 0 경계를 다시 검사한다.
- 지속 이동으로 바뀌면 dt 적분과 swept collision 등 터널링 방지 검증을 추가한다.

## 피할 구현과 축소 기준

- 실제 다중 사용자 동기화가 핵심이면 단일 reducer만으로 충분하지 않다.
- 렌더 프레임 수를 행동 횟수로 쓰거나 충돌 후 좌표만 되돌리지 않는다.
- 시간 부족이면 애니메이션을 제거하고 상태 전이 표와 재시작을 유지한다.

1순위 도구는 [Python 표준 라이브러리](../../tools/python-stdlib.md)다. 이 작은 합성 입력에는 패키지 설치·외부 호출이 필요 없다. Python도 실행할 수 없으면 표에 후보를 전부 적고 손계산한다. 대규모 개선 도구는 설치·규정·입력 적합성이 확인된 이후 별도 선택한다.

## 연습 시간 예산과 효과 측정

30분: 상태 전이 세 건. 90분: 격자와 사유 표시. 180분: 입력 반복과 에너지0 테스트. 권장 연습 예산이다.

벽 통과 횟수, 중복 이벤트 추가 소비량, 경계 위반 수를 측정한다. 이 합성 예제만으로 실제 조직의 시간 절감·만족도·수익 향상을 주장할 수 없다.
