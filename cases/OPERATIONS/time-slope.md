## 1. 창작 업무 요청
창작 요청: 건조실 담당자가 센서 표가 오르는 것은 알지만 측정 간격이 들쭉날쭉해 변화 속도를 비교하기 어렵다고 한다.
독립적으로 설계한 합성 연습이다. 공개 자료는 일반 구현 원리의 참고이며 아래 정책·수치는 창작이다.

## 2. 숨은 원인과 다른 목표
- 샘플 간격이 달라 단순 행 차이가 오해를 만든다.
- 시간대 또는 단위가 섞였다.
- 한 번의 튀는 값이 전체 추세를 지배한다.

## 3. 방향을 바꾸는 질문
| 질문 | 답에 따른 변경 |
|---|---|
| 변화 속도를 어느 기간에 보고 싶은가? | 선택 창 고정 후 계산; 여러 창을 사후 골라 유리한 결과 선택 금지. |
| 시간은 실제 관측 시각인가? | 수신 시각이면 지연 확인 전 추세 해석 보류. |
| 경보를 내야 하는가 단순 추세 보고인가? | 경보면 별도 승인 임계값 필요; 본 예제 기울기만 보고. |

## 4. 데이터와 없을 때의 대안
필수 t_hours 수치, value 수치. 한 행은 관측 한 건, 시각 고유. null 값은 미확인으로 본 작은 예제 전체 보류. value 단위는 예제 수분지표 점수. 기준시각은 고정, 행 번호를 시간으로 사용 금지.
필수 필드가 없으면 결과를 0으로 채우지 않고 unknown을 표시하고 위 질문의 해당 담당자에게 확인한다. 선택 자료는 기준 방법 통과 후 요청한다.

```json
{
  "rows": [
    [
      0,
      10
    ],
    [
      1,
      12
    ],
    [
      3,
      16
    ]
  ]
}
```

## 5. 기준 방법과 개선 조건
최소제곱 기울기 Σ(t−평균t)(v−평균v)/Σ(t−평균t)^2를 계산한다. 분모0이면 invalid. 시간 축과 원시 점을 같이 표시.

비선형·이상점이 중요하면 구간별 비교나 강건한 추세를 별도 기준과 대조한다.

## 6. 최소 구현과 다음 행동
입력 JSON/표 → 필수 필드·단위 검사 → 측정값이 시간당 얼마나 바뀌는지 계산 → 입력·근거·판정 상태를 한 화면에 표시 → 담당자가 결과를 수용하거나 미확인 자료를 보완한다.
외부 모델·자동 전송 없이 로컬 표 또는 Python 표준 라이브러리로 시작한다. 실행 허용이 미확인이면 계산 절차와 Markdown만 읽는다.

## 7. 합성 입력과 기대 결과
각 input은 위 fixture의 최상위 키를 교체한다. 입력 배열은 전체 교체이며, 기대값은 손계산으로 정한 고정 oracle이다.
| 종류 | 입력 변화 | 기대 결과 | 근거 |
|---|---|---|---|
| 정상 | `{}` | `2.0` | 모든 점이 value=10+2t 위에 있어2점/시간. |
| 경계 | `{"rows": [[0, 10], [1, 10]]}` | `0.0` | 변화 없음. |
| 정보 부족 | `{"rows": [[0, 10], [1, null]]}` | `"unknown"` | 관측 부족을0으로 대체하지 않음. |

[실행 검사](../../examples/synthetic/check_expansion_b.py)와 [고정 fixture](../../examples/synthetic/expansion_b.json)는 앱 구현을 가져오지 않는 작은 계산 예제다. 통과는 위 입력과 판정에만 해당하며 생산 시스템 검증이 아니다.

## 8. 오용과 범위 축소
기울기 하나로 원인을 추정하지 않는다. 예측 모델은 시간축 오류의 해결책이 아니다. 단위 미확인 시 관측표만 제공.
추가 패키지 설치가 불가하면 같은 입력을 표와 손계산으로 검사한다. 시간 부족 시 선택 기능을 줄이고 미확인 상태·필수 규칙·기대값 검사는 유지한다.

## 9. 구현물에 대한 담당자 피드백
- 시간당 단위를 보고 점검 시기를 결정할 수 있는가?
- 한 점을 제외하면 결과가 달라지는지 확인하고 싶은가?

담당자에게 결과를 보여주고 실제 다음 행동을 선택하게 한다. 완료 건수/관찰 건수, 오류와 우회 행동을 기록한다. 만족도와 업무 효과는 이 합성 검사로 입증되지 않는다.
