## 1. 창작 업무 요청
창작 요청: 공용 공조실 담당자가 경보 후 점검 항목이 많아 첫 확인 대상을 고르기 어렵다고 한다.
독립적으로 설계한 합성 연습이다. 공개 자료는 일반 구현 원리의 참고이며 아래 정책·수치는 창작이다.

## 2. 숨은 원인과 다른 목표
- 점검 순서가 관행으로 고정되어 시간을 낭비한다.
- 확률 추정이 현재 설비 조건과 맞지 않는다.
- 안전상 반드시 먼저 할 점검이 점수에 묻힌다.

## 3. 방향을 바꾸는 질문
| 질문 | 답에 따른 변경 |
|---|---|
| 반드시 먼저 해야 하는 안전 점검이 있는가? | 있으면 그 절차가 우선이다. 본 예제는 필수 점검 완료 후 선택이다. |
| 발견 확률은 어떤 기록에서 추정했는가? | 근거가 없으면 확률 순위 대신 수동 체크리스트를 사용한다. |
| 첫 항목만 필요한가, 전체 점검 계획인가? | 전체 계획이면 상관과 검사 결과에 따른 갱신이 필요하다. 본 예제는 첫 항목을 고르는 휴리스틱이다. |

## 4. 데이터와 없을 때의 대안
필수 필드는 id, probability(0~1), minutes(0보다 큰 분)이다. 한 행은 필수 안전 절차 완료 후의 선택 점검이다. probability는 해당 원인 발견의 조건부 추정치이며 서로 독립이라고 가정하지 않는다. null은 미확인이다. 안전 절차 정보를 확인하지 못하면 운영 추천을 실행하지 않는다.
필수 필드가 없으면 결과를 0으로 채우지 않고 unknown을 표시하고 위 질문의 해당 담당자에게 확인한다. 선택 자료는 기준 방법 통과 후 요청한다.

```json
{
  "checks": [
    {
      "id": "a",
      "p": 0.6,
      "minutes": 3
    },
    {
      "id": "b",
      "p": 0.2,
      "minutes": 0.5
    }
  ]
}
```

## 5. 기준 방법과 개선 조건
필수 안전 절차를 완료한 뒤 확률/분 비율을 계산하고 가장 큰 항목 하나를 제안한다. 동률은 id 순으로 처리한다. 전체 최적 점검 순서라고 표현하지 않는다.

점검 결과와 소요시간을 기록하여 다음 확인 확률을 갱신하는 순차 정책을 검토한다.

## 6. 최소 구현과 다음 행동
입력 JSON/표 → 필수 필드·단위 검사 → 제한된 점검 시간에서 첫 확인 항목을 고른다 → 입력·근거·판정 상태를 한 화면에 표시 → 담당자가 결과를 수용하거나 미확인 자료를 보완한다.
외부 모델·자동 전송 없이 로컬 표 또는 Python 표준 라이브러리로 시작한다. 실행 허용이 미확인이면 계산 절차와 Markdown만 읽는다.

## 7. 합성 입력과 기대 결과
각 input은 위 fixture의 최상위 키를 교체한다. 입력 배열은 전체 교체이며, 기대값은 손계산으로 정한 고정 oracle이다.
| 종류 | 입력 변화 | 기대 결과 | 근거 |
|---|---|---|---|
| 정상 | `{}` | `"b"` | a=0.2/분,b=0.4/분. |
| 경계 | `{"checks": [{"id": "a", "p": 0.2, "minutes": 1}, {"id": "b", "p": 0.4, "minutes": 2}]}` | `"a"` | 동률은id순. |
| 정보 부족 | `{"checks": [{"id": "a", "p": null, "minutes": 1}]}` | `"unknown"` | 추정확률없음. |

[실행 검사](../../examples/synthetic/check_expansion_b.py)와 [고정 fixture](../../examples/synthetic/expansion_b.json)는 앱 구현을 가져오지 않는 작은 계산 예제다. 통과는 위 입력과 판정에만 해당하며 생산 시스템 검증이 아니다.

## 8. 오용과 범위 축소
확률 점수로 안전 필수 절차를 건너뛰지 않는다. 인과모형 없이 전체 최적화 성과를 주장하지 않는다. 확률 근거가 부족하면 시간과 점검 설명만 표시한다.
추가 패키지 설치가 불가하면 같은 입력을 표와 손계산으로 검사한다. 시간 부족 시 선택 기능을 줄이고 미확인 상태·필수 규칙·기대값 검사는 유지한다.

## 9. 구현물에 대한 담당자 피드백
- 첫 점검을 선택한 이유를 이해하는가?
- 필수 절차가 끝나지 않았을 때 추천을 멈출 수 있는가?

담당자에게 결과를 보여주고 실제 다음 행동을 선택하게 한다. 완료 건수/관찰 건수, 오류와 우회 행동을 기록한다. 만족도와 업무 효과는 이 합성 검사로 입증되지 않는다.

## 10. 개발자 본인의 설명 사전 연습

- b를 선택한 손계산을 보여줄 수 있는가?
