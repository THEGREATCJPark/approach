## 1. 창작 업무 요청
창작 요청: 보관함 구매팀이 품질 통과 후보 중 가격과 납기 위험을 한 점수로 섞자 선정 이유를 설명하기 어렵다고 한다.
독립적으로 설계한 합성 연습이다. 공개 자료는 일반 구현 원리의 참고이며 아래 정책·수치는 창작이다.

## 2. 숨은 원인과 다른 목표
- 가중치를 누가 정했는지 모른다.
- 후보별 장단점이 하나의 점수에 가려진다.
- 필수 품질 미달도 평균 점수로 살아남는다.

## 3. 방향을 바꾸는 질문
| 질문 | 답에 따른 변경 |
|---|---|
| 필수 품질은 이미 별도로 승인되었는가? | 아니면 gate부터 적용한다. 본 예제에는 승인된 후보만 있다. |
| 비용, 납기, 위험 중 필수 상한이 있는가? | 있으면 비지배 계산 전에 상한 미달 후보를 제외한다. |
| 최종 선택인가 선택지 설명인가? | 설명이면 Pareto 표, 최종 선택이면 권한자의 우선순위를 추가로 확인한다. |

## 4. 데이터와 없을 때의 대안
필수 필드는 id, cost(동일 화폐 단위), lead_days(일), risk(같은 척도의 수치)다. 한 행은 품질 승인 후보다. null인 축은 미확인이므로 unknown이며 0은 유효 관측이다. 척도와 방향은 사전에 확정한다.
필수 필드가 없으면 결과를 0으로 채우지 않고 unknown을 표시하고 위 질문의 해당 담당자에게 확인한다. 선택 자료는 기준 방법 통과 후 요청한다.

```json
{
  "rows": [
    {
      "id": "a",
      "v": [
        10,
        2,
        3
      ]
    },
    {
      "id": "b",
      "v": [
        12,

      ]
    },
    {
      "id": "c",
      "v": [
        15,
        1,
        2
      ]
    }
  ]
}
```

## 5. 기준 방법과 개선 조건
다른 후보가 모든 축에서 같거나 좋고 한 축 이상에서 엄격히 좋으면 해당 후보는 지배된다. 비지배 후보와 제외 근거를 표시하되 자동으로 단일 대안을 선택하지 않는다.

권한자가 가중치나 필수 상한을 정하면 민감도와 선택 변화를 추가한다.

## 6. 최소 구현과 다음 행동
입력 JSON/표 → 필수 필드·단위 검사 → 필수 품질 승인 후 대안 간 장단점을 표시한다 → 입력·근거·판정 상태를 한 화면에 표시 → 담당자가 결과를 수용하거나 미확인 자료를 보완한다.
외부 모델·자동 전송 없이 로컬 표 또는 Python 표준 라이브러리로 시작한다. 실행 허용이 미확인이면 계산 절차와 Markdown만 읽는다.

## 7. 합성 입력과 기대 결과
각 input은 위 fixture의 최상위 키를 교체한다. 입력 배열은 전체 교체이며, 기대값은 손계산으로 정한 고정 oracle이다.
| 종류 | 입력 변화 | 기대 결과 | 근거 |
|---|---|---|---|
| 정상 | `{}` | `["a", "c"]` | a는b보다모든축우수;c는비싸지만빠르고위험낮음. |
| 경계 | `{"rows": [{"id": "a", "v": [10, 2, 3]}, {"id": "b", "v": [10, 2, 3]}]}` | `["a", "b"]` | 동일벡터는엄격지배아님. |
| 정보 부족 | `{"rows": [{"id": "a", "v": [10, null, 3]}]}` | `"unknown"` | 납기미확인. |

[실행 검사](../../examples/synthetic/check_expansion_b.py)와 [고정 fixture](../../examples/synthetic/expansion_b.json)는 앱 구현을 가져오지 않는 작은 계산 예제다. 통과는 위 입력과 판정에만 해당하며 생산 시스템 검증이 아니다.

## 8. 오용과 범위 축소
Pareto 집합을 최고 품질 순위로 표현하지 않는다. 서로 다른 위험 척도를 그대로 비교하지 않는다. 축이 미확인이면 자료 표까지만 제공한다.
추가 패키지 설치가 불가하면 같은 입력을 표와 손계산으로 검사한다. 시간 부족 시 선택 기능을 줄이고 미확인 상태·필수 규칙·기대값 검사는 유지한다.

## 9. 구현물에 대한 담당자 피드백
- 비싼 후보가 남은 이유를 이해하는가?
- 최종 선택을 위해 추가로 정해야 하는 우선순위가 보이는가?

담당자에게 결과를 보여주고 실제 다음 행동을 선택하게 한다. 완료 건수/관찰 건수, 오류와 우회 행동을 기록한다. 만족도와 업무 효과는 이 합성 검사로 입증되지 않는다.

## 10. 개발자 본인의 설명 사전 연습
PREP에서만 사용한다. 실제 AI 금지 후속 평가에서는 질문 생성·답변 작성·실시간 코칭을 모두 중단한다.
- b를 제외하고 c를 남긴 수치 근거는 무엇인가?
- 비지배가 유일한 최적해를 뜻하지 않는 이유는 무엇인가?
