## 요청과 다른 해석

“시설 점검 순서는 정해져 있는데 모든 방문 약속을 지키는 출발시간을 알고 싶다.”

- 고정 경로의 출발 시각 교집합 문제다.
- 대기 허용이면 제약식이 바뀐다.
- 총시간 최소가 아니라 늦게 출발하는 것이 목표일 수 있다.

## 우선 질문과 방향 변화

1. 현장에서 기다릴 수 있는가? → 대기 불가의 구간 교집합과 대기 허용 시뮬레이션을 구분한다.
2. 시간창은 도착 기준인가 작업 완료 기준인가? → 완료 기준이면 서비스 분을 차감한다.
3. 순서 변경을 허용하는가? → 허용하면 별도 경로 후보 탐색으로 전환한다.

파일에서 이미 확인되는 답은 다시 묻지 않는다. 정책을 결정할 권한자와 기준 시점을 함께 기록한다.

## 데이터 계약과 합성 입력

정차 한 행. id 기본키, offset 출발 후 도착까지 누적 분(이전 서비스 포함), open/close는 당일 00:00 후 분. 시간창 양끝 포함. 연습에서는 대기 불가.

최소 필수는 아래 판정 필드와 키다. 대표 샘플·스키마로 시작하며 개인 식별 정보는 필요하지 않다. 개선용 데이터는 실제 작업 시간과 오류 기록이다. 전체 이력이나 외부 API는 첫 검증에 없어도 된다. null은 미확인이며 0·false와 다르다. 필수 필드가 없으면 해당 판정을 보류하고 담당자 확인 목록에 남긴다.

```json
[
  {
    "id": "A",
    "offset": 10,
    "open": 540,
    "close": 560
  },
  {
    "id": "B",
    "offset": 25,
    "open": 560,
    "close": 590
  },
  {
    "id": "C",
    "offset": 40,
    "open": 580,
    "close": 600
  }
]
```

## 기준 방법, 제약과 최소 경로

각 정차에서 출발 가능 구간 [open-offset,close-offset]를 만들고 교집합을 구한다. 개선은 실제 교통변동의 시나리오별 구간 비교다.

필수: 고정 순서, 대기 불가, 모든 도착창 준수. 목적은 가능 구간 산출; 늦은 출발 선호가 합의되면 상한을 선택한다.

정차표 → 출발 구간 540~550분(09:00~09:10) → 출발550이면 도착560/575/590 → 운영자가 09:10 출발을 선택한다.

## 기대 결과와 반례

| 유형 | 입력 또는 변경 | 기대 결과 |
|---|---|---|
| 정상 | 기본 입력 | 가능 출발540~550 |
| 경계 | 출발550 | A560 B575 C590 모두 허용 |
| 정보 부족 | B offset=null | 출발 가능 판정 보류 |
| 충돌 | C open=600,close=600 | C 출발560 요구, 교집합 없음 |
| 순서변경 | 정차 행 역순, offset 유지 | 구간540~550 유지 |
| 새 샘플 | 전체 시간창+60 | 가능 출발600~610 |

손계산 근거: A [530,550], B [535,565], C [540,560]. 하한 max=540, 상한 min=550. 순서가 아닌 이미 산출한 offset의 제약 교집합이므로 행순서 불변이다.

비슷하지만 다른 두 건: 출발550은 A 마감560에 도착해 허용, 출발551은 A561로 위반이다.

작은 계산 예제는 [check_c.py](../../examples/synthetic/check_c.py)에서 별도 표준 라이브러리 계산으로 확인한다. 각 수용 테스트 행의 기대값은 소형 오라클 계산으로 확인한다. 전체 앱·화면·DB 동시성은 구현하거나 검증하지 않았으며, 기대값 검증과 구현물 테스트 통과는 다르다. 실행 범위는 해당 스크립트 출력과 검증 보고서를 따른다.

## 답변이 바뀌면 수정할 계획

- 대기 허용 답변이면 빠른 도착을 기다림으로 처리하며 이 교집합 공식을 그대로 쓰지 않는다.
- 완료 기준이면 각 stop 서비스시간을 받아 상한부터 다시 계산한다.

## 피할 구현과 축소 기준

- 대기 허용이나 시간의존 이동시간에 이 선형 교집합을 그대로 적용하지 않는다.
- 누적 offset을 각 구간 시간과 혼동하지 않는다.
- 시간 부족이면 지도 대신 출발구간·각 도착시간 표를 유지한다.

1순위 도구는 [Python 표준 라이브러리](../../tools/python-stdlib.md)다. 이 작은 합성 입력에는 패키지 설치·외부 호출이 필요 없다. Python도 실행할 수 없으면 표에 후보를 전부 적고 손계산한다. 대규모 개선 도구는 설치·규정·입력 적합성이 확인된 이후 별도 선택한다.

## 연습 시간 예산과 효과 측정

30분: 구간 세 개 손계산. 90분: 출발 시각 입력과 위반 표. 180분: 지연 시나리오 비교. 권장 연습 예산이다.

허용 출발구간 길이와 시간창 위반 수를 측정한다. 이 합성 예제만으로 실제 조직의 시간 절감·만족도·수익 향상을 주장할 수 없다.
