## 1. 창작 업무 요청

“현장 수거 상자를 두 차량에 나눠 실으려는데 총 용량은 충분해도 배정이 되지 않는다.”

## 2. 다른 원인과 목표

- 상자 분할 불가 때문에 합계 검사를 넘어야 한다.
- 용량 단위가 중량인지 부피인지 다를 수 있다.
- 차량별 접근 제한이 실제 원인일 수 있다.

## 3. 먼저 확인할 질문과 분기

1. 상자를 나눌 수 있는가? → 아니면 이산 배정, 가능하면 수량 흐름으로 바꾼다.
2. 차량 용량은 같은 단위인가? → 단위 확인 전 계산을 보류한다.
3. 미배정을 허용하는가? → 허용하면 이유와 잔여량을 표시한다.

자료에서 이미 확인되는 답은 다시 묻지 않는다. 정책 답변이 충돌하면 기준 시점과 결정 권한을 확인하고 기존 가정을 기록한다.

## 4. 데이터 계약

boxes는 상자id→정수 부피단위, capacities는 차량별 정수 용량. 상자 한 건은 분할 불가이며 정확히 한 차량 배정. null은 부피 미측정.

위 필드는 최소 필수다. 운영 중 오류·수동 수정 기록은 개선에 유용하고 전체 개인 이력은 첫 실험에 필요하지 않다. 필수 값이 null이면 미확인으로 처리하며 0이나 false로 바꾸지 않는다. 자료를 받을 수 없으면 아래 합성 입력으로 계산만 확인하고 실제 판정은 보류한다.

```json
{
  "boxes": {
    "a": 4,
    "b": 3,
    "c": 2
  },
  "capacities": [
    5,
    4
  ]
}
```

## 5. 기준 방법과 개선 조건

작은 입력은 모든 차량 배정 조합을 열거해 용량을 검사한다. 총합≤총용량은 필요조건일 뿐 충분조건이 아니다. 대규모에서는 적합한 이산 최적화 도구를 검토한다.

1순위 도구는 [Python 표준 라이브러리](../../tools/python-stdlib.md)다. 설치 없이 작은 목록·집합·정수 연산으로 시작한다. 실행이 허용되지 않거나 Python이 없으면 후보 표와 손계산을 남긴다. 외부 API·자격증명은 필요 없다. 복잡한 패키지는 데이터 크기와 실패 사례가 기준 방법의 한계를 보여준 뒤 검토한다.

## 6. 최소 구현과 다음 행동

상자·차량 표 → 가능 배정 또는 불가능 사유 → 운영자가 차량 추가나 상자 재포장을 결정한다.

완료 기준은 실제 입력 한 건에서 판정·근거·미확인 사유·다음 행동이 이어지는 것이다. 합성 테스트 통과는 실제 사용자 만족이나 업무 효과를 입증하지 않는다.

## 7. 정상·경계·정보 부족 기대값

| 유형 | 입력 | 기대 결과 | 독립 계산 근거 |
|---|---|---|---|
| normal | `{"boxes":{"a":4,"b":3,"c":2},"capacities":[5,4]}` | `true` | a를4차량,b+c=5를5차량에 배정. |
| boundary | `{"boxes":{"a":3,"b":3,"c":3},"capacities":[5,4]}` | `false` | 합계9=용량9지만 어떤 차량도 상자2개6을 못 싣는다. |
| missing | `{"boxes":{"a":null},"capacities":[5]}` | `"unknown"` | 상자 부피 미측정. |
| missing_capacity | `{"boxes":{"A":3},"capacities":[null]}` | `"unknown"` | 차량 용량 미확인은 가능 판정을 보류한다. |

[실행 오라클](../../examples/synthetic/check_expansion_c.py)은 각 기대값을 다시 계산한다. 이는 문서 기대값 검증이며 완성 앱·동시 사용자·현장 운영 테스트가 아니다.

## 8. 잘못된 적용과 범위 축소

- 방문 순서·시간창을 이 용량 배정 결과만으로 해결했다고 하지 않는다.
- 총합 비교만으로 가능을 판정하지 않는다.

시간이 부족하면 장식·선택 기능을 줄이고 입력 계약, 미확인 처리, 위 기대값 검증을 유지한다. 효과는 동일 업무의 전후 완료 시간·오류 수와 측정 대상 수를 확보한 뒤 판단한다.
