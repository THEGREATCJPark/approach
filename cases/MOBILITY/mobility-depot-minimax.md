## 1. 창작 업무 요청

“이동 상담팀의 출발 거점을 정할 때 일부 지역만 지나치게 멀어지지 않게 하고 싶다.”

## 2. 다른 원인과 목표

- 평균 이동보다 최장 이동 최소화가 목표다.
- 특정 지역 수요가 많으면 가중 평균 목표가 더 적합할 수 있다.
- 부지 사용 가능 여부는 별도 필수조건이다.

## 3. 먼저 확인할 질문과 분기

1. 평균과 최장 중 무엇이 우선인가? → 최장이면 minimax, 평균이면 가중 합으로 바꾼다.
2. 후보 거점은 실제 사용 가능한가? → 불가 후보를 점수 계산 전에 제거한다.
3. 거리 대신 이동시간을 써야 하는가? → 업무 판단 단위를 확정한다.

자료에서 이미 확인되는 답은 다시 묻지 않는다. 정책 답변이 충돌하면 기준 시점과 결정 권한을 확인하고 기존 가정을 기록한다.

## 4. 데이터 계약

거점 한 행: id 키, times는 동일 순서 방문지별 비음수 정수 분. 모든 방문지를 포함한 완전 행렬 필수. 후보별 최대값 최소, 동점id.

위 필드는 최소 필수다. 운영 중 오류·수동 수정 기록은 개선에 유용하고 전체 개인 이력은 첫 실험에 필요하지 않다. 필수 값이 null이면 미확인으로 처리하며 0이나 false로 바꾸지 않는다. 자료를 받을 수 없으면 아래 합성 입력으로 계산만 확인하고 실제 판정은 보류한다.

```json
{
  "depots": [
    [
      "A",
      [
        2,
        9
      ]
    ],
    [
      "B",
      [
        6,
        6
      ]
    ]
  ]
}
```

## 5. 기준 방법과 개선 조건

후보마다 행 최대를 계산해 가장 작은 것을 고른다. 평균·총합도 참고로 보이되 목표를 섞지 않는다. 새 후보 위치를 연속적으로 찾는 문제와 구별한다.

1순위 도구는 [Python 표준 라이브러리](../../tools/python-stdlib.md)다. 설치 없이 작은 목록·집합·정수 연산으로 시작한다. 실행이 허용되지 않거나 Python이 없으면 후보 표와 손계산을 남긴다. 외부 API·자격증명은 필요 없다. 복잡한 패키지는 데이터 크기와 실패 사례가 기준 방법의 한계를 보여준 뒤 검토한다.

## 6. 최소 구현과 다음 행동

후보 행렬 → 거점별 최대 이동·평균 → 담당자가 최장 이동 목표에 맞는 후보를 검토한다.

완료 기준은 실제 입력 한 건에서 판정·근거·미확인 사유·다음 행동이 이어지는 것이다. 합성 테스트 통과는 실제 사용자 만족이나 업무 효과를 입증하지 않는다.

## 7. 정상·경계·정보 부족 기대값

| 유형 | 입력 | 기대 결과 | 독립 계산 근거 |
|---|---|---|---|
| normal | `{"depots":[["A",[2,9]],["B",[6,6]]]}` | `{"id": "B", "worst": 6}` | A최대9,B최대6;B선택. |
| boundary | `{"depots":[["A",[0]],["B",[0]]]}` | `{"id": "A", "worst": 0}` | 둘 다0이면id순. |
| missing | `{"depots":[["A",[2,null]],["B",[6,6]]]}` | `"unknown"` | A의 최대값을 확정할 수 없어 전 후보 비교 보류. |

[실행 오라클](../../examples/synthetic/check_expansion_c.py)은 각 기대값을 다시 계산한다. 이는 문서 기대값 검증이며 완성 앱·동시 사용자·현장 운영 테스트가 아니다.

## 8. 잘못된 적용과 범위 축소

- 총 이동 최소와 최대 이동 최소가 같은 목표라고 가정하지 않는다.
- 일부 방문지 누락을0으로 채우지 않는다.

시간이 부족하면 장식·선택 기능을 줄이고 입력 계약, 미확인 처리, 위 기대값 검증을 유지한다. 효과는 동일 업무의 전후 완료 시간·오류 수와 측정 대상 수를 확보한 뒤 판단한다.

## 9. 구현물에 대한 사용자 피드백

1. 최장 이동을 줄이기 위해 평균이 늘어나는 선택도 받아들일 수 있는가?
2. 실제로 사용할 수 없는 거점이 결과에 섞여 있지 않은가?

설명 전에 사용자가 한 건을 처리하게 하고 실패·우회·추가 질문을 관찰한다. 새 요구를 오류 수정·필수 누락·선택 개선으로 분류한다.
