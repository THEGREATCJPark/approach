## 1. 창작 업무 요청

“방문 요청이 흩어져 있어 가까운 지점들을 먼저 묶어 담당 구역 초안을 만들고 싶다.”

## 2. 다른 원인과 목표

- 거리 임계값 연결요소로 빠른 초안이 가능하다.
- 연쇄 연결 때문에 묶음 전체 직경은 클 수 있다.
- 구역별 수용량 제약이 있으면 단순 군집으로 부족하다.

## 3. 먼저 확인할 질문과 분기

1. 가까움은 두 지점 직접 거리인가 연결로 이어짐인가? → 직접 직경 상한이면 다른 군집 제약이 필요하다.
2. 구역 수 또는 담당자 용량이 고정인가? → 고정이면 배정 문제로 확장한다.
3. 좌표 단위가 평면m인가? → 위경도라면 적절한 거리 변환을 먼저 한다.

자료에서 이미 확인되는 답은 다시 묻지 않는다. 정책 답변이 충돌하면 기준 시점과 결정 권한을 확인하고 기존 가정을 기록한다.

## 4. 데이터 계약

points는 [id,x] 평면 직선상의 미터 좌표, radius 비음수m. 거리≤radius 간선을 만들고 연결요소를 구한다. 좌표null은 미측정.

위 필드는 최소 필수다. 운영 중 오류·수동 수정 기록은 개선에 유용하고 전체 개인 이력은 첫 실험에 필요하지 않다. 필수 값이 null이면 미확인으로 처리하며 0이나 false로 바꾸지 않는다. 자료를 받을 수 없으면 아래 합성 입력으로 계산만 확인하고 실제 판정은 보류한다.

```json
{
  "points": [
    [
      "A",
      0
    ],
    [
      "B",
      3
    ],
    [
      "C",
      9
    ]
  ],
  "radius": 4
}
```

## 5. 기준 방법과 개선 조건

모든 쌍 거리를 비교한 뒤 BFS로 연결요소를 찾는다. 결과는 후보 구역이며 차량 경로나 공정한 배정을 보장하지 않는다. 규모 증가 시 공간 색인을 검토한다.

1순위 도구는 [Python 표준 라이브러리](../../tools/python-stdlib.md)다. 설치 없이 작은 목록·집합·정수 연산으로 시작한다. 실행이 허용되지 않거나 Python이 없으면 후보 표와 손계산을 남긴다. 외부 API·자격증명은 필요 없다. 복잡한 패키지는 데이터 크기와 실패 사례가 기준 방법의 한계를 보여준 뒤 검토한다.

## 6. 최소 구현과 다음 행동

좌표 → 근접 간선·연결 묶음 → 담당자가 긴 연쇄 묶음을 분할 검토한다.

완료 기준은 실제 입력 한 건에서 판정·근거·미확인 사유·다음 행동이 이어지는 것이다. 합성 테스트 통과는 실제 사용자 만족이나 업무 효과를 입증하지 않는다.

## 7. 정상·경계·정보 부족 기대값

| 유형 | 입력 | 기대 결과 | 독립 계산 근거 |
|---|---|---|---|
| normal | `{"points":[["A",0],["B",3],["C",9]],"radius":4}` | `[["A", "B"], ["C"]]` | AB3≤4,BC6>4. |
| boundary | `{"points":[["A",0],["B",4],["C",8]],"radius":4}` | `[["A", "B", "C"]]` | AB와BC가경계4로 연결;AC8이어도같은요소. |
| missing | `{"points":[["A",null],["B",4]],"radius":4}` | `"unknown"` | 좌표미확인. |

[실행 오라클](../../examples/synthetic/check_expansion_c.py)은 각 기대값을 다시 계산한다. 이는 문서 기대값 검증이며 완성 앱·동시 사용자·현장 운영 테스트가 아니다.

## 8. 잘못된 적용과 범위 축소

- 연결요소를 모든 지점이 반경 안에 모인 원형 구역이라고 설명하지 않는다.
- 위경도 차이를미터로 취급하지 않는다.

시간이 부족하면 장식·선택 기능을 줄이고 입력 계약, 미확인 처리, 위 기대값 검증을 유지한다. 효과는 동일 업무의 전후 완료 시간·오류 수와 측정 대상 수를 확보한 뒤 판단한다.

## 9. 구현물에 대한 사용자 피드백

1. 긴 연쇄 묶음을 보고 실제 담당 구역을 나눌 수 있는가?
2. 고립 지점의 처리 책임을 정하는 데 도움이 되는가?

설명 전에 사용자가 한 건을 처리하게 하고 실패·우회·추가 질문을 관찰한다. 새 요구를 오류 수정·필수 누락·선택 개선으로 분류한다.
