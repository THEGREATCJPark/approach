# 사용자 관찰과 짧은 설문

대상은 구현물의 사용자다. 개발자의 설명 능력은 측정하지 않는다. [업무 피드백](prototype-feedback.md)에서 동일 과제를 수행한 뒤 수집한다. 참여·기록·자료 처리는 해당 환경의 허용 범위를 따른다.

| 범주 | 중립 질문 | 관찰·응답 기록 |
|---|---|---|
| 핵심 업무 | 제시된 작업을 완료했습니까? | 완료/도움받아 완료/미완료와 원인 |
| 다음 행동 | 결과를 보고 다음에 무엇을 하시겠습니까? | 실제 필요한 행동과 일치 여부 |
| 근거 이해 | 판단에 사용된 근거를 어디서 확인했습니까? | 근거 위치를 찾았는지 |
| 오류 구별 | 오류와 정보 부족을 어떻게 구별했습니까? | 오해한 상태·표시 |
| 누락 | 결정을 위해 더 필요한 정보는 무엇입니까? | 누락 필드와 목적 |
| 기존 방식 | 기존 방식과 비교해 어느 단계가 더 쉽거나 어려웠습니까? | 단계와 이유; 변화 없음도 허용 |
| 재사용 | 다시 사용하기 전에 충족되어야 할 조건은 무엇입니까? | 신뢰·운영·정확성 요구 |

## 측정 계약

- 완료율 = 독립적으로 완료한 시도 수 / 전체 유효 시도 수. 도움받은 완료는 별도 집계한다.
- 시간 = 과제 제시부터 완료 선언까지 초. 중단·시간초과는 따로 기록하고 성공 사례 평균에만 숨기지 않는다.
- 오류 = 미리 정의한 오판정·누락·잘못된 다음 행동의 건수. 클릭 수와 오류 수를 혼동하지 않는다.
- 만족도 질문을 추가하면 척도 양 끝과 응답 수를 표시한다. 관찰된 완료 여부와 별도 지표다.
- 전후 비교는 같은 난이도·같은 측정법·연습 효과를 고려한다. 실제 전후 측정이 없으면 시간 절감은 예상이다.
- 작은 표본, 자발적 참여 편향, 모의 사용자 여부를 공개한다. 결과를 조직 전체의 개선 효과로 일반화하지 않는다.

기록 양식: [피드백](../templates/feedback-log.md). 분모·도움 여부·측정 조건이 없는 비율을 보고하지 않는다.
