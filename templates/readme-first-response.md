# README 붙여넣기 후 첫 응답 양식

실제 요구를 읽은 뒤 채운다. 빈 칸을 그대로 출력하지 않으며, 이미 확인된 내용은 재질문하지 않는다.
[처리 절차](../playbooks/readme-intake.md)를 먼저 읽는다. 실제 작업 기록은 별도 허용 공간에 둔다.

## 권장 접근과 이유

“이번 작업은 [사용자]가 [행동]할 수 있는 [제출물]을 만드는 일입니다. 원문의 [근거]에 따라 [주 접근법]부터 진행하는 것이 적합합니다.”

## 원문에서 확인한 범위

| 요구 ID | 확인한 요구와 원문 근거 | 구현할 결과 | 검증 기준 |
|---|---|---|---|
| R… | 실제 원문에서 추출 | 화면/데이터/처리 | 통과 여부를 판단할 관찰 |

필수 요구를 빠뜨리지 않는다. 선택 기능·명시적 제외는 별도로 짧게 정리한다.
자료 상태: **본문 확인 / 파일 열람 확인 / 파일명만 언급 / 미제공**을 구분한다.

## 먼저 확인할 자료와 핵심 질문

자료 최대3개: 무엇을 열어 어떤 필드·단위·관계를 확인할지 적는다. 열 수 있다면 먼저 확인한다.
담당자 질문 최대3개: 그대로 복사해 보낼 문장과 답에 따라 달라지는 결정을 적는다.
질문이 없으면 “현재 제공 내용으로 시작할 수 있어 추가 질문은 없습니다.”라고 적는다.

## 구현 순서

| 순서 | 지금 할 일 | 만들어질 결과 | 다음 단계 기준 |
|---|---|---|---|
| 1 | 첫 입력 한 건부터 | 최소 경로 | 실제 기대 결과 한 건 |
| … | 남은 필수 요구 | 요구 ID와 연결 | 검증 가능 기준 |

답을 기다리는 부분과 지금 진행할 수 있는 부분을 표시한다. 일정은 확인된 제한 시간에 맞추고, 없으면 임의의 시험 시간을 가정하지 않는다.

## 검증과 범위 축소

정상·경계·자료 부족 각각의 입력/기대 결과. 필수 규칙은 유지하고 선택 기능부터 줄인다.
실행 전이면 “실행할 검사”라고 말한다. 아직 실행하지 않은 것을 통과했다고 쓰지 않는다.

## 참고한 가이드와 다음 행동

실제로 읽은 사례1~3개·필요한 방법/도구 경로, 선택 이유와 적용하지 않을 가정을 간단히 적는다.
저장소 접근에 실패한 경우 확인하지 못한 경로를 명시한다. 설치·API 호출이 필요한지는 따로 표시한다.
마지막은 지금 할 작업 또는 필요한 답변으로 끝낸다. 이미 구현 권한이 있으면 중복 승인을 요구하지 않는다.
